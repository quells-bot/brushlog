# BrushLog on iOS (Tauri)

The iOS app wraps the same SvelteKit build as the web PWA in a
[Tauri 2](https://v2.tauri.app/) shell. Every asset ships inside the app and
loads from a local origin, so the app launches and works with no network.

- Bundle ID: `me.kaiwells.brushlog`
- Xcode project: `src-tauri/gen/apple/` (generated by `tauri ios init`, then
  edited — **don't re-run `tauri ios init`**, it would wipe the app icon wiring
  in `project.yml`)
- App icon: `src-tauri/gen/apple/BrushLog.icon` (Icon Composer document)

## 1. One-time toolchain

```bash
# Rust + iOS targets
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
rustup target add aarch64-apple-ios aarch64-apple-ios-sim

# Point the command-line tools at Xcode (needs your password)
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer

# Node 24 + pnpm (pnpm switches to the version pinned in package.json)
brew install node@24 pnpm cocoapods xcodegen
pnpm install
```

`tauri ios init` needs CocoaPods; `xcodegen` regenerates the Xcode project after
`project.yml` edits. If CocoaPods warns about encoding, add
`export LANG=en_US.UTF-8` to your shell profile.

## 2. Sign in to Xcode

1. **Xcode → Settings… → Accounts → + → Apple Account**, sign in with the
   Apple ID that has the paid Developer Program membership.
2. Select the team → **Manage Certificates… → + → Apple Development**.
3. The Team ID (10 characters) is already set in
   `src-tauri/tauri.conf.json` (`bundle.iOS.developmentTeam`) and
   `src-tauri/gen/apple/project.yml` (`DEVELOPMENT_TEAM`).

Signing is **automatic**: Xcode creates and renews certificates and
provisioning profiles for `me.kaiwells.brushlog` as needed.

## 3. Run in the Simulator

```bash
pnpm tauri ios build --debug --target aarch64-sim
```

Then drag `src-tauri/gen/apple/build/arm64-sim/BrushLog.app` onto a booted
Simulator, or run `pnpm ios:dev` for live reload against the Vite dev server.

## 4. Run on your iPhone

1. Connect the iPhone by cable, unlock it, and tap **Trust**.
2. On the phone: **Settings → Privacy & Security → Developer Mode → On**
   (restarts the phone).
3. Live-reload development (phone and Mac on the same Wi-Fi):

   ```bash
   pnpm ios:dev
   ```

   This loads from the Mac's dev server, so it is **not** offline. For the
   real, bundled app use the release install below.

4. First time only — register the phone with your team. `pnpm ios:build`
   builds for a generic device, so it never registers one and fails with
   "Your team has no devices". Build once against the phone itself (it gets as
   far as the "Build Rust Code" step and stops there; that's expected — the
   device is registered and the profile created by then):

   ```bash
   xcrun devicectl list devices   # note the phone's Identifier
   cd src-tauri/gen/apple && xcodebuild -allowProvisioningUpdates \
     -allowProvisioningDeviceRegistration -scheme brushlog_iOS \
     -workspace brushlog.xcodeproj/project.xcworkspace -configuration release \
     -destination id=<device-id> build; cd -
   ```

5. Release install (bundled, works offline):

   ```bash
   pnpm ios:build
   xcrun devicectl device install app --device <device-id> src-tauri/gen/apple/build/arm64/BrushLog.ipa
   ```

Check on the phone: haptics on each zone change and at the end, the icon in
light / dark / tinted home-screen styles, and — with Airplane Mode on and the
app force-quit — that it still launches and logs a session.

## 5. TestFlight

1. In [App Store Connect](https://appstoreconnect.apple.com/) → **Apps → + →
   New App**: platform iOS, name BrushLog, bundle ID `me.kaiwells.brushlog`,
   any SKU (e.g. `brushlog`).
2. Build an App Store archive. Each upload needs a higher build number:

   ```bash
   pnpm ios:build --export-method app-store-connect --build-number 1
   ```

3. Upload, either:
   - **Xcode**: `pnpm tauri ios build --open`, then **Product → Archive →
     Distribute App → App Store Connect → Upload**; or
   - **Command line**, with an App Store Connect API key (Users and Access →
     Integrations → Keys, role _Developer_; save the `.p8` to
     `~/.appstoreconnect/private_keys/`):

     ```bash
     xcrun altool --upload-app -t ios -f src-tauri/gen/apple/build/arm64/BrushLog.ipa \
       --apiKey <KEY_ID> --apiIssuer <ISSUER_ID>
     ```

4. In App Store Connect → **TestFlight**, add yourself as an internal tester
   (answer the export-compliance question: BrushLog uses no encryption beyond
   what iOS provides). Install the **TestFlight** app on the phone and accept
   the invite. TestFlight builds expire after 90 days.

## 6. Move your history from the PWA

IndexedDB in the Safari PWA and in the app are separate. Once:

1. In the home-screen PWA: **Settings → Export history**.
2. In the app: **Settings → Import history**, pick the file.

Importing merges and skips duplicates, so it is safe to repeat.

## How the two builds differ

The Tauri CLI sets `TAURI_ENV_PLATFORM` while it runs `pnpm build` / `pnpm dev`:

- `vite.config.js` drops the PWA plugin (no service worker, no manifest).
- `svelte.config.js` ignores `BASE_PATH` (the app always serves from `/`).
- `src/hooks.server.js` strips the `<!--pwa-->` manifest link from `app.html`.

Platform differences in app code live in `src/lib/platform.js` (`haptic`,
`exportFile`). Storage goes through `src/lib/store.js` over a backend
(`src/lib/storage/idb.js` today), so a SQLite backend can be added for iOS
without touching callers.
